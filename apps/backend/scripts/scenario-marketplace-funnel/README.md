# Сценарий S2–S4: воронка сделки целиком

Продолжение [scenario-5-suppliers](../scenario-5-suppliers/README.md). Одна заявка →
5 КП → выбор → чат → escrow-сделка → выплата; и отдельная ветка: спор → возврат админом.

## Шаги

| | что происходит | проверяется |
|---|---|---|
| **S2** | R1: 5 поставщиков шлют КП с разной ценой/сроком; заказчик открывает «Предложения», сравнивает, принимает лучшее по цене → открывается чат, рождается сделка `AWAITING_PAYMENT` | 5 КП видны заказчику; принят самый дешёвый; чат создан |
| **S3** | R1: админ пополняет кошелёк заказчика → оплата (`HELD`) → поставщик отгружает (`SHIPPED`) → заказчик подтверждает (`RELEASED`) → деньги на кошельке компании-поставщика | сделка `RELEASED`; поставщику пришла выплата |
| **S4** | R2: вторая заявка, принятое КП, оплата, отгрузка → заказчик открывает спор (`DISPUTED`) | сделка `DISPUTED`; спор виден в админ-панели |

Решение спора (возврат) делает `screenshot.mjs` от имени админа — это ровно то,
что делает кнопка «Вернуть покупателю» в панели `:5175`.

## Запуск

```bash
# стек: docker compose up -d ; бэкенд :3000 ; фронт :5173 ; админка :5175
#   pnpm --filter @huphup/admin run dev
cd apps/backend/scripts/scenario-marketplace-funnel
node run.mjs          # прогон воронки → state.json
node screenshot.mjs   # 11 скринов в screenshots/ (в середине — возврат от админа)
```

`node ../scenario-lib/reset.mjs` — очистить сценарные заявки/сделки/чаты/кошельки
между прогонами (аккаунты сохраняются). `--all` — снести и аккаунты/компании/товары.

## Баги, которые нашли и починили этим прогоном

- **Поставщик на «Балансе» видел 0.** `BalancePage` читал `/wallets/me` (всегда
  персональный кошелёк по `userId`), а деньги по сейф-сделке идут на кошелёк
  **компании**. Фронт переведён на `/billing/wallet` + `/billing/transactions`
  (там `ownerForUser`: поставщику — кошелёк компании, остальным — личный) +
  подпись «Кошелёк компании …». Скрин `07`.
- **`−−1 575 000 ₸`** — двойной минус: `billing.move` хранит расход со знаком,
  а `BalancePage` ещё и сам дорисовывал `−`. Берём модуль суммы. Скрин `06`.
- **`GET /products/catalog?q=...` → 400** — `@Query() pagination: PaginationQueryDto`
  + глобальный `forbidNonWhitelisted` рубили `q`/`city`. Добавлен
  `ProductCatalogQueryDto extends PaginationQueryDto`. Регресс покрыт
  `product.dto.spec.ts` + `products.service.spec.ts`.
